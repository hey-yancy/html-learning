## 16.1 内容模型与嵌套规则

HTML 元素按「内容模型」分类，规则写错时浏览器会**自动纠错重建 DOM**，导致样式和 JS 选择器全部失效。

| 内容模型 | 含义 | 代表元素 |
| --- | --- | --- |
| 块级 / 流式内容 Flow | 可包含大多数元素，独占一行 | `div` `p` `section` `ul` `table` |
| 短语内容 Phrasing | 行内文字级内容 | `span` `a` `strong` `em` `img` `code` |
| 嵌入内容 Embedded | 引入外部资源 | `img` `video` `iframe` `canvas` `svg` |
| 交互内容 Interactive | 用户可操作 | `a` `button` `input` `select` `textarea` |
| 透明内容 Transparent | 继承父元素的内容模型 | `a` `ins` `del` `object` |
| 空元素 Void | 无内容、无结束标签 | `br` `hr` `img` `input` `meta` `link` |

必须记住的硬性规则：

1. `<p>` 只能包含短语内容；遇到 `div`、`h2`、`ul` 等块级标签会**自动闭合段落**。
2. `<ul>` / `<ol>` 的直接子元素**只能是 `<li>`**（`script`、`template` 除外），嵌套列表要放进 `li`。
3. `<a>` 不能嵌套 `<a>`，也不能包含交互内容（如按钮）。
4. `<table>` 有严格顺序：`caption` → `colgroup` → `thead` → `tbody` / `tfoot` → `tr` → `th` / `td`；浏览器会补 `tbody`。
5. `<form>` 不能嵌套 `<form>`；一个控件可通过 `form="表单id"` 关联到页面任意位置的表单。
6. `<button>` 默认 `type="submit"`，放在表单里的普通按钮必须写 `type="button"`。
7. `<h1>`~`<h6>` 不能互相嵌套；标题层级要连续，不跳级。
8. `<label>` 同时只能关联一个控件（`for` 或包裹，二选一优先 `for`）。

```html
<!-- 错误：p 里嵌 div，浏览器会自动把 p 拆成两段 -->
<p>开头<div>块级内容</div>结尾</p>

<!-- 正确：块级容器放外面 -->
<div><p>开头</p><p>块级内容</p><p>结尾</p></div>
```

## 16.2 废弃标签与现代替代方案

HTML5 移除了纯表现层标签。看到老代码要能认出来，并知道换成什么。

| 废弃 / 不推荐 | 曾用途 | 现代替代 |
| --- | --- | --- |
| `<font>` `<basefont>` | 字体、颜色、字号 | CSS `font` / `color` |
| `<center>` | 居中 | CSS `text-align` / Flex / Grid |
| `<big>` `<small>`(滥用) | 字号 | CSS `font-size`；`<small>` 现在表「附属说明」 |
| `<b>` `<i>`(滥用) | 加粗 / 斜体 | 语义用 `<strong>` `<em>`，纯视觉用 CSS |
| `<u>` | 下划线 | CSS `text-decoration`（`<u>` 现表「拼写错误」等） |
| `<strike>` `<s>`(部分) | 删除线 | `<del>`（文档修订）/ CSS |
| `<marquee>` `<blink>` | 滚动 / 闪烁 | CSS 动画，且应避免闪烁 |
| `<frameset>` `<frame>` | 框架页 | `<iframe>` 或服务端 / 前端路由 |
| `<applet>` `<embed>`(旧用法) | 插件 | `<object>` / 原生 API |
| `<table>` 做布局 | 页面排版 | Flex / Grid |
| `<br><br>` 撑间距 | 留白 | CSS `margin` / `gap` |
| `<acronym>` `<dir>` | 缩写 / 目录列表 | `<abbr>` / `<ul>` |

> **注意**：废弃 ≠ 浏览器不支持，而是**没有语义、不可访问、不可维护**。

## 16.3 head 进阶：SEO、社交卡片与资源提示

```html
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>不超过 60 字符｜站点名</title>
  <meta name="description" content="150 字以内，会显示在搜索结果摘要里">
  <meta name="robots" content="index,follow"><!-- 或 noindex,nofollow -->
  <meta name="theme-color" content="#e44d26">
  <link rel="canonical" href="https://example.com/page">
  <link rel="alternate" hreflang="en" href="https://example.com/en/page">

  <!-- 社交分享（Open Graph / Twitter Card） -->
  <meta property="og:type" content="website">
  <meta property="og:title" content="分享标题">
  <meta property="og:description" content="分享摘要">
  <meta property="og:image" content="https://example.com/cover.png">
  <meta property="og:url" content="https://example.com/page">
  <meta name="twitter:card" content="summary_large_image">

  <!-- 图标与资源提示 -->
  <link rel="icon" href="/favicon.ico" sizes="any">
  <link rel="apple-touch-icon" href="/icon-180.png">
  <link rel="preconnect" href="https://fonts.example.com">
  <link rel="dns-prefetch" href="https://cdn.example.com">
  <link rel="preload" as="style" href="/critical.css">
  <link rel="stylesheet" href="/style.css">
  <script src="/app.js" defer></script>
</head>
```

| 元素 | 作用 |
| --- | --- |
| `robots` | 告诉爬虫是否索引、是否跟随链接 |
| `canonical` | 指定权威 URL，合并重复页面的权重 |
| `hreflang` | 多语言 / 多地区版本对应关系 |
| `og:*` | 微信、QQ、Facebook 等分享卡片的标题 / 摘要 / 封面 |
| `preconnect` / `dns-prefetch` | 提前建连 / 提前 DNS 解析第三方域名 |
| `preload` | 高优先级预加载当前页必需资源（必须写 `as`） |
| `prefetch` | 低优先级预取**下一页**可能用的资源 |

> **常见坑**：`preload` 只下载不执行，仍需对应的 `link` / `script` 使用；滥用 preload 反而抢占带宽。

## 16.4 资源加载与性能属性

| 写法 | 下载 | 执行 / 应用 | 顺序 |
| --- | --- | --- | --- |
| 普通 `<script src>` | 阻塞 HTML 解析 | 下载完立即执行 | 按书写顺序 |
| `defer` | 并行下载，不阻塞解析 | DOM 解析完成后、DOMContentLoaded 前 | **保证顺序** |
| `async` | 并行下载 | 下载完立即执行，可能打断解析 | 不保证顺序 |
| `type="module"` | 并行下载 | 默认 defer 行为，支持 import | 按依赖顺序 |
| `<link rel="stylesheet">` | 阻塞渲染 | 构建 CSSOM | 按书写顺序 |
| `loading="lazy"` | 视口附近才加载 | 图片 / iframe 生效 | — |
| `fetchpriority="high"` | 提高优先级 | LCP 大图常用 | — |
| `decoding="async"` | 异步解码图片 | 减少主线程阻塞 | — |

配套的完整性属性：

- `crossorigin="anonymous"`：跨域资源以匿名 CORS 方式请求，配合 canvas 读取像素、错误堆栈。
- `integrity="sha384-..."`：SRI 子资源完整性校验，CDN 资源被篡改时拒绝加载。
- `referrerpolicy="no-referrer"`：控制请求携带的 Referer 信息。

## 16.5 图片进阶：响应式与布局稳定

```html
<!-- 按视口宽度与像素密度选择资源 -->
<picture>
  <source media="(min-width: 1000px)" srcset="cover-lg.webp" type="image/webp">
  <source media="(min-width: 600px)"  srcset="cover-md.webp" type="image/webp">
  <img src="cover-sm.jpg" alt="课程封面" width="800" height="450"
       loading="lazy" decoding="async" fetchpriority="high">
</picture>

<!-- 仅按密度切换 -->
<img src="a.jpg" srcset="a.jpg 1x, a@2x.jpg 2x, a@3x.jpg 3x" alt="头像" width="96" height="96">
```

要点：

- `<picture>` 里**必须保留 `<img>` 作为兜底**，`alt` 写在 `img` 上；`source` 用 `media` / `type` 依次匹配，浏览器取第一个可用的。
- `srcset` + `sizes` 让浏览器根据视口与 DPR 自己挑图，比 JS 判断更可靠。
- 显式 `width` / `height`（或 CSS `aspect-ratio`）预留空间，避免图片加载后页面跳动（CLS）。
- 首屏大图不要加 `loading="lazy"`，会拖慢 LCP；首屏以下的长列表图片才用懒加载。
- `alt` 写法：描述**内容与功能**，不写「图片」「照片」；装饰性图片写 `alt=""`（让屏幕阅读器跳过）。

## 16.6 iframe 进阶：sandbox 与权限

```html
<iframe src="widget.html" title="天气小组件" width="400" height="260"
        loading="lazy" referrerpolicy="no-referrer"
        sandbox="allow-scripts allow-forms allow-popups"></iframe>
```

| sandbox 值 | 放开的能力 |
| --- | --- |
| 不写任何值 | 全部限制：无脚本、无表单、无弹窗、无同源、无 top 导航 |
| `allow-scripts` | 允许执行脚本（**不含** DOM 同源访问） |
| `allow-same-origin` | 保留原始 origin（与 allow-scripts 同用会大幅削弱隔离，谨慎） |
| `allow-forms` | 允许提交表单 |
| `allow-popups` | 允许 window.open / target=_blank |
| `allow-top-navigation` | 允许改写顶层页面（一般**不要**给） |
| `allow-downloads` | 允许下载 |

其他要点：`title` 必写（屏幕阅读器靠它识别）；`srcdoc` 可直接内联 HTML（本笔记的运行效果预览正是用它）；跨域 iframe 无法用 JS 读取内部 DOM，需 `postMessage` 通信；响应式嵌入用外层 `aspect-ratio` + 内部 `width/height:100%`。

## 16.7 表单进阶：提交、关联与校验

**enctype 三种取值**

| 值 | 用途 |
| --- | --- |
| `application/x-www-form-urlencoded` | 默认值，普通文本表单 |
| `multipart/form-data` | **含文件上传时必须用** |
| `text/plain` | 纯文本，仅调试用 |

**控件与表单的关联**

```html
<form id="user-form" action="/api/user" method="post" enctype="multipart/form-data">
  <fieldset>
    <legend>基本信息</legend>
    <label for="avatar">头像</label>
    <input id="avatar" name="avatar" type="file" accept="image/*" multiple>
  </fieldset>
</form>

<!-- 放在表单外，仍能关联提交 -->
<input form="user-form" name="source" value="homepage" type="hidden">
<button form="user-form" type="submit">保存</button>
<button form="user-form" type="submit" formaction="/api/draft" formmethod="get">存草稿</button>
```

其他要点：

- `fieldset disabled` 可一次性禁用整组控件；被禁用控件**不参与提交**。
- `autocomplete="username" | "current-password" | "new-password" | "off"` 等 token 帮助密码管理器正确填充。
- 多选/复选用 `name="tags[]"` 形式，后端按数组接收。
- 原生校验：`required` `pattern` `min/max` `minlength/maxlength` `step`；JS 可用 `checkValidity()`、`setCustomValidity()`、`validity` 对象自定义提示。
- 原生校验只是**用户体验层**，服务端必须重新校验全部数据（永远不要信任客户端）。

## 16.8 表格与可访问性进阶

```html
<table>
  <caption>学期成绩汇总</caption>
  <colgroup><col span="1" style="width:30%"><col span="3"></colgroup>
  <thead>
    <tr><th id="name" scope="col">姓名</th><th id="html" scope="col">HTML</th>
        <th id="css" scope="col">CSS</th><th id="total" scope="col">总评</th></tr>
  </thead>
  <tbody>
    <tr><th headers="name" scope="row">同学 A</th>
        <td headers="name html">95</td><td headers="name css">90</td><td headers="name total">优秀</td></tr>
  </tbody>
</table>
```

- `scope="col|row|colgroup|rowgroup"` 声明表头作用范围；复杂表格可用 `headers` + `id` 精确关联。
- `caption` 必须是 `table` 的第一个子元素；`summary` 属性已废弃，说明文字放 `caption` 或表格外的段落。
- 可访问性五条规则（ARIA）：① 能用原生标签就别用 ARIA；② 不要改变原生语义；③ 所有交互必须支持键盘；④ 可聚焦元素不要用 `role="presentation"` / `aria-hidden="true"`；⑤ 所有交互元素都要有可访问名称。
- 常用补充：`aria-label` / `aria-labelledby`（命名）、`aria-describedby`（说明）、`aria-live="polite"`（动态播报）、`role="alert"`（错误提示）、`role="navigation"` 等 landmark。
- 「跳到主内容」链接：页面第一个可聚焦元素指向 `<main id="main">`，方便键盘与读屏用户跳过导航。
- 文字与背景对比度至少 4.5:1（大字号 3:1），不要只用颜色传达状态。

## 16.9 SEO、结构化数据与浏览器解析

**SEO 基础清单**：唯一且描述准确的 `title` / `description` · 语义化标签与连续标题层级 · 有意义的 `alt` · 规范 URL（canonical）· 移动友好（viewport）· 合理的内部链接与锚文本 · 页面加载性能。

**结构化数据（JSON-LD）**：让搜索引擎理解「这是一篇文章 / 课程 / 商品」，从而展示富摘要。

```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Article",
  "headline": "HTML 完整学习笔记",
  "datePublished": "2026-11-18",
  "author": { "@type": "Person", "name": "作者" }
}
</script>
```

**浏览器解析补充**：

1. 请求 → 字节流按编码解码 → 词法分析成 token → 构建 DOM 树；CSS 同时构建 CSSOM。
2. DOM + CSSOM → 渲染树 → 布局（Layout）→ 绘制（Paint）→ 合成（Composite）。
3. HTML 解析是**容错的**：标签没闭合、嵌套错误时浏览器按规则自动补全，所以「能显示」不代表「写对了」。
4. 标准模式 / 怪异模式由 DOCTYPE 决定，影响盒模型、行高、百分比高度等。
5. 输出到页面的用户输入必须转义（`<` → `&lt;` 等），否则会造成 XSS；现代框架的模板插值默认做这件事。

## 16.10 术语表

| 术语 | 含义 |
| --- | --- |
| DOM | 浏览器把 HTML 解析成的树状对象模型，JS 通过它读写页面 |
| CSSOM | CSS 规则构成的对象模型，与 DOM 合成渲染树 |
| DOCTYPE | 文档类型声明，决定标准 / 怪异渲染模式 |
| 语义化 | 用标签表达内容含义，而非只表达外观 |
| a11y | Accessibility 缩写，可访问性 |
| ARIA | 为辅助技术补充角色、状态、属性的规范 |
| SEO | 搜索引擎优化 |
| CLS | 累积布局偏移，图片不写尺寸会导致页面跳动 |
| LCP | 最大内容绘制，核心性能指标之一 |
| CORS / SRI | 跨域资源共享 / 子资源完整性校验 |
| Void element | 空元素，没有内容与结束标签 |
| 布尔属性 | 只要出现即生效，如 `required`、`hidden` |
| 实体 | `&name;` 形式，用于显示保留字符 |
| XSS | 跨站脚本攻击，源于未转义的用户输入 |
| 响应式 | 同一页面适配不同屏幕尺寸 |
| Polyfill | 为旧浏览器补齐新特性的脚本 |
| Web Components | 自定义元素 + Shadow DOM + 模板的组件方案 |

**排错速查**

| 症状 | 优先排查 |
| --- | --- |
| 中文乱码 | 文件保存编码 vs `charset` 位置 |
| 图片不显示 | `src` 路径、大小写、是否被 CSP / 懒加载影响 |
| 样式不生效 | link 路径、选择器权重、被行内样式覆盖、缓存 |
| 表单数据缺失 | `name`、`disabled`、`enctype` |
| 布局错位 | 标签未闭合、p 嵌 div、colspan 计算、iframe 尺寸 |
| 移动端字很小 | 缺 `viewport` |
| 脚本找不到元素 | 脚本执行太早 → 加 `defer` 或放到 body 末尾 |

## 本章复习自测

<details>
<summary>1. 哪些元素可以作为 `<ul>` 的直接子元素？嵌套列表应该放在哪？</summary>

只能是 `<li>`（`script` / `template` 除外）；嵌套的 `ul` / `ol` 必须放在某个 `<li>` 内部。

</details>

<details>
<summary>2. `defer`、`async`、`type="module"` 三者的执行时机？</summary>

defer 并行下载、DOM 解析完后按顺序执行；async 下载完立即执行、不保证顺序；module 默认具备 defer 行为并支持 import，按依赖顺序执行。

</details>

<details>
<summary>3. 含文件上传的表单必须设置什么？被禁用控件会提交吗？</summary>

`enctype="multipart/form-data"`；被 `disabled` 的控件不参与提交，`readonly` 会提交。

</details>

<details>
<summary>4. 为什么图片建议显式写 width / height？首屏大图能加 loading="lazy" 吗？</summary>

预留空间避免 CLS 布局跳动；首屏大图不应懒加载，否则会拖慢 LCP，懒加载适合首屏以下的图片。

</details>

<details>
<summary>5. ARIA 的第一原则是什么？原生校验能替代服务端校验吗？</summary>

能用原生语义标签就不用 ARIA；原生校验只是体验层，服务端必须重新校验所有数据。

</details>
