01

认识 HTML：网页的骨架

概念、术语、浏览器渲染流程 —— 先把地图看清楚，再出发。

1.1 HTML 是什么

HTML（HyperText Markup Language，超文本标记语言）不是编程语言，而是描述网页结构与内容的标记语言。它用一对对标签把文字、图片、链接等包起来，告诉浏览器「这是一级标题」「那是一个按钮」。

  • 超文本：不只是文字，还能通过链接跳到另一个文档。
  • 标记：用 <tag> 这类标签给内容打上语义标记。
  • 三大分工：HTML 管结构，CSS 管样式，JavaScript 管行为。三者配合才有现代网页。

1.2 浏览器拿到 HTML 之后做了什么

阶段做了什么
1. 请求输入网址，浏览器向服务器发起 HTTP 请求，拿到 .html 文本
2. 解析从上到下解析标签，构建 DOM 树（Document Object Model）
3. 加载遇到 <link> / <img> / <script> 继续请求 CSS、图片、脚本
4. 渲染结合 CSS 生成渲染树，计算布局，绘制到屏幕
5. 交互JavaScript 操作 DOM，响应用户点击、输入等事件
补充说明

HTML 是容错的：写错标签浏览器也不会崩溃，会尽力猜测你的意图。但「能显示」不等于「写对了」——结构错误会影响 SEO、可访问性和后续维护。

1.3 三个必须分清的术语

术语含义例子
标签 Tag尖括号包住的关键字，分开始标签与结束标签<p> 与 </p>
元素 Element开始标签 + 内容 + 结束标签的整体<p>你好</p>
属性 Attribute写在开始标签里，提供附加信息，形式 名="值"<a href="..."> 中的 href

还有一类空元素（void element）没有内容和结束标签，例如 <img>、<br>、<input>、<meta>、<link>、<hr>。HTML5 里写 <img ... /> 也可以，斜杠会被忽略。

本节速记：HTML = 结构；标签 → 元素 → 属性；空元素无结束标签；浏览器解析 HTML 生成 DOM 树再渲染。
02

开发环境与第一个页面

DOCTYPE、html / head / body 骨架、注释、空白折叠与路径规则。

2.1 最小可运行文档骨架

一个规范的 HTML5 文档由 <!DOCTYPE html> 声明和 <html> 根元素组成，根元素内固定包含 <head>（元信息，不显示）与 <body>（可见内容）。

必写项

<!DOCTYPE html> 必须放在第一行：它告诉浏览器使用标准模式渲染，省略会触发怪异模式，导致 CSS 盒模型表现异常。<meta charset="UTF-8"> 必须放在 head 最前面（前 1024 字节内），否则中文可能乱码。

2.2 骨架逐行拆解

写法作用
<!DOCTYPE html>HTML5 文档声明，不是标签
<html lang="zh-CN">根元素；lang 声明语言，利于屏幕阅读器与搜索引擎
<meta charset="UTF-8">字符编码，中文必写
<meta name="viewport">移动端视口设置，响应式页面必写
<title>标签页标题，也是搜索结果标题
<body>所有用户可见内容

配套工具：编辑器推荐 VS Code（装 Live Server 插件可热刷新）；浏览器按 F12 打开开发者工具，Elements 面板能看到实时 DOM。

2.3 注释、空白折叠与路径

注释写作 <!-- 注释内容 -->，不会显示在页面上，也不能嵌套。HTML 会把连续多个空格、换行、制表符折叠成一个空格；需要保留格式就用 <pre> 或 CSS 的 white-space。

路径写法含义示例
同级相对路径从当前文件所在目录找src="logo.png"
下级相对路径进入子目录src="images/logo.png"
上级相对路径../ 返回上一层href="../index.html"
根相对路径从站点根目录开始src="/assets/logo.png"
绝对 URL完整协议 + 域名https://example.com/a.png
本节速记：DOCTYPE 第一行 → html → head + body；charset 与 viewport 必写；注释不嵌套；空白会被折叠；路径分相对与绝对。
03

文本与排版标签

标题、段落、强调、引用、代码，以及块级与行内的区别。

3.1 常用文本标签速览

标签语义类型
<h1> ~ <h6>一到六级标题，h1 一个页面建议只用一次块级
<p>段落，浏览器自动在上下留间距块级
<br> <hr>换行 / 主题分隔线（都是空元素）—
<strong> <em>重要 / 强调，带语义，优于 b / i行内
<del> <ins>删除线 / 下划线（表示文档修订）行内
<sub> <sup>下标 / 上标行内
<blockquote>块引用，可配 cite 属性块级
<pre> <code>预格式 / 行内代码块级 / 行内
<div> <span>无语义容器：块级 / 行内，用于布局与样式钩子块级 / 行内

3.2 块级元素 vs 行内元素

块级元素独占一行、可设宽高与上下外边距（如 div、p、h1、ul）；行内元素跟在文字流里、宽高由内容决定（如 span、a、strong）。还有 img、input 这类行内块：不换行但可设宽高。

常见坑

不要为了「变大加粗」就滥用 <h1>，也不要用 <br><br> 撑间距。视觉交给 CSS，语义交给 HTML。另外 <p> 里不能嵌 <div>，浏览器会自动把段落闭合。

本节速记：标题有层级、段落成块；强调优先 strong / em；样式用 CSS，结构用语义标签；块级换行、行内随文。
04

链接与图片

a 的各类 href、锚点跳转、img 的 alt、figure 与响应式图片。

4.1 超链接 a

写法效果
href="page.html"跳转到站内页面
href="https://..."跳转外部站点
href="#ch-05"跳到本页 id="ch-05" 的锚点
href="mailto:a@b.com"唤起邮件客户端
href="tel:13800000000"移动端拨号
href="a.pdf" download下载而非打开
target="_blank"新标签页打开，务必加 rel="noopener"
title="说明"鼠标悬停提示（不能替代 alt / 文字说明）
安全提示

使用 target="_blank" 时加上 rel="noopener noreferrer"，避免新页面通过 window.opener 反向操作原页面。

4.2 图片 img 与 figure

<img src="..." alt="..."> 是空元素。alt 是必写属性：图片加载失败时显示替代文字，也是屏幕阅读器与搜索引擎理解图片的唯一依据。装饰性图片可写 alt=""。显式声明 width / height 能避免加载时的布局抖动（CLS）。

需要「图 + 说明」时用 <figure> 包住 <img> 和 <figcaption>；需要按屏幕密度/宽度换图时用 <picture> + <source> + srcset。

本节速记：href 支持页面 / 锚点 / 邮件 / 电话 / 下载；_blank 要配 noopener；img 必写 alt，配 figure 更语义化。
05

列表：无序、有序与描述列表

ul / ol / dl 的用法、常用属性与嵌套规则。

5.1 三种列表

标签用途常用属性
<ul><li>无序列表，项目无先后顺序CSS list-style
<ol><li>有序列表，有步骤/排名含义start、type、reversed
<dl><dt><dd>描述列表：术语 + 解释一个 dt 可对应多个 dd

<li> 里可以再嵌 <ul> / <ol> 形成多级列表，但必须嵌在 li 内部，不能直接放在 ul 下。列表项里也能放段落、链接、图片等任意内容。

本节速记：ul 无顺序、ol 有顺序、dl 是术语解释；嵌套列表只能放进 li 里；ol 支持 start / reversed / type。
06

表格：结构与合并单元格

表格只用来展示「二维数据」，不要拿它做页面布局。

6.1 表格的完整结构

标签作用
<table>表格容器
<caption>表格标题，写在 table 内第一个位置
<thead> / <tbody> / <tfoot>表头 / 表体 / 表脚，语义分组，便于长表格分页打印
<tr>表格行（table row）
<th>表头单元格，默认加粗居中；用 scope="col|row" 指明方向
<td>普通数据单元格
<colgroup> / <col>按列统一设置样式

即使不写 <tbody>，浏览器也会自动补上。语义化分组让 CSS 选择器和屏幕阅读器更准确。

6.2 colspan 与 rowspan

colspan="2" 表示横向占两列，rowspan="2" 表示纵向占两行。合并后要删掉被覆盖的单元格，否则表格会错位。

注意

表格的默认边框、间距由浏览器决定，实际项目用 CSS 的 border-collapse、padding 控制。移动端常用外层 overflow-x:auto 的容器包裹表格以横向滚动。

本节速记：caption → thead / tbody / tfoot → tr → th / td；表头加 scope；合并单元格后删除多余格子；表格不做布局。
07

表单：与用户对话的入口

form、input 全类型、label、校验属性与提交原理。

7.1 form 的工作方式

用户填写控件 → 点击提交 → 浏览器把带 name 的控件按 name=value 打包 → 按 method 发送到 action 指定的地址。没有 name 的控件不会被提交。

属性说明
action接收数据的 URL，留空表示提交到当前页
method="get"数据拼在 URL 查询串里，适合搜索、筛选（不适合密码）
method="post"数据放在请求体里，适合登录、写入操作
enctype上传文件必须设为 multipart/form-data
autocomplete / novalidate自动填充 / 关闭原生校验

7.2 input 类型一览

type用途type用途
text单行文本（默认值）password密码，输入被遮蔽
email / url / tel带格式校验与移动端键盘优化number数字，配 min / max / step
radio单选，同组 name 必须相同checkbox多选，name 常用数组形式
date / time / datetime-local原生日期时间选择器month / week月 / 周选择
range滑块color取色器
file文件上传，配 multiple / accepthidden隐藏字段
search搜索框submit / reset / button提交 / 重置 / 普通按钮

7.3 其它控件与 label

<label> 有两种关联写法：用 for 指向控件的 id，或直接把控件包在 label 里。关联后点击文字也能聚焦/勾选控件，对可访问性很关键。

  • <textarea rows cols>：多行文本；<select> + <option> + <optgroup>：下拉选择
  • <fieldset> + <legend>：给一组控件加分组标题
  • <datalist> + list：给输入框提供候选建议（仍可自由输入）
  • <button type="submit|reset|button">：比 input 按钮更灵活，可放图标

7.4 HTML5 原生校验

属性作用
required必填
placeholder占位提示（不能替代 label）
pattern正则校验，如 pattern="[0-9]{11}"
min / max / minlength / maxlength数值或长度范围
checked / selected / disabled / readonly布尔属性：写上即生效
autofocus / autocomplete自动聚焦 / 自动填充策略
提示

原生校验只是用户体验层，服务端必须重新校验所有数据。布尔属性写成 required="false" 依然是「必填」——只要属性存在就生效。

本节速记：name 决定提交什么，method 决定怎么发；label 必配；select / textarea / fieldset 各司其职；原生校验不能替代服务端校验。
08

语义化与页面结构

HTML5 结构标签、SEO 与可访问性，写出「机器也读得懂」的页面。

8.1 HTML5 结构标签地图

标签含义
<header>页面或区块的头部（logo、标题、导航）
<nav>主导航链接集合
<main>页面主内容，一个页面只能有一个
<article>可独立分发的内容：文章、帖子、卡片
<section>带主题的内容分组，通常有标题
<aside>侧边栏、与主体相关的补充信息
<footer>页脚：版权、联系方式、相关链接
<figure> / <figcaption>独立的图、表、代码块及其说明
<time datetime="">机器可读的时间
<mark> / <details> / <summary>高亮 / 可折叠详情

8.2 语义化的收益

  • 可访问性：屏幕阅读器可以「跳到主内容」「列出所有导航」。
  • SEO：搜索引擎更容易判断哪部分是正文、标题层级是否正确。
  • 可维护性：<nav> 一眼就懂，比 <div class="nav"> 少一层心智负担。
  • 健壮性：样式丢失时页面仍保有清晰的结构与阅读顺序。
常见误区

语义化不等于「把所有 div 换掉」：纯布局容器继续用 div；<section> 应当有标题，只是想加样式时用 div；标题层级要连续，别从 h1 直接跳到 h4。

本节速记：header / nav / main / article / section / aside / footer 各就各位；main 只能一个；语义化服务 a11y 与 SEO；纯布局仍用 div。
09

多媒体与嵌入内容

audio / video、内联 SVG、canvas、iframe 与响应式嵌入。

9.1 音视频标签

标签 / 属性说明
<video src controls>视频播放器；poster 封面、width/height 尺寸
<audio src controls>音频播放器
<source src type>提供多种格式，浏览器挑第一个能播的
<track kind="subtitles">字幕文件（WebVTT），配 srclang / label
autoplay / loop / muted / preload自动播放 / 循环 / 静音 / 预加载策略
补充

主流浏览器对自动播放有限制：带声音的 autoplay 通常被拦截，需同时加 muted 或由用户手势触发。

9.2 SVG、Canvas 与 iframe

  • 内联 SVG：矢量、可用 CSS 控制、可缩放不失真，适合图标与图表；直接写在 HTML 里。
  • canvas：位图画布，靠 JavaScript 逐帧绘制，适合游戏与图像处理；标签本身只是占位。
  • iframe：嵌入另一个页面。务必写 title 说明用途；用 sandbox 限制权限；用 loading="lazy" 延迟加载。
  • 响应式嵌入：外层容器设 aspect-ratio 或 padding-top，内部 iframe/video 设 width:100%;height:100%。
本节速记：video / audio 配 source 提供多格式；SVG 矢量、canvas 位图；iframe 必写 title 并考虑 sandbox 与懒加载。
10

head 元信息与资源引入

页面「看不见但很重要」的部分：编码、视口、SEO、图标与脚本加载策略。

10.1 head 里的常驻元素

元素作用
<title>标签页标题、收藏夹名称、搜索结果标题
<meta charset="UTF-8">字符编码，必须最靠前
<meta name="viewport">width=device-width, initial-scale=1.0
<meta name="description">搜索结果摘要，约 150 字以内
<link rel="stylesheet" href>引入外部 CSS
<link rel="icon" href>站点图标 favicon
<style> / <script>内联样式 / 脚本
<base href target>统一设置相对 URL 的基准（谨慎使用）

一份可直接复制的 head 模板

<!-- head 内建议顺序（静态代码块，无需运行效果）-->
<meta charset="UTF-8">
<meta name="viewport" content="width=device-width, initial-scale=1.0">
<title>页面标题</title>
<meta name="description" content="一句话描述本页内容">
<link rel="icon" href="favicon.ico">
<link rel="stylesheet" href="style.css">
<script src="app.js" defer></script>

10.2 defer 与 async 的区别

写法下载执行时机顺序
普通 <script src>阻塞 HTML 解析下载完立即执行按书写顺序
defer并行下载HTML 解析完、DOMContentLoaded 前保证顺序
async并行下载下载完立刻执行，可能打断解析不保证顺序

页面脚本推荐 defer；第三方统计类、互不依赖的脚本适合 async。

10.3 社交分享与 SEO 元信息

Open Graph 协议让链接在微信、QQ、Twitter 等平台展示标题、摘要和封面，常用 <meta property="og:title">、og:description、og:image、og:url。此外 <link rel="canonical"> 指定权威 URL，避免重复内容分散权重。

本节速记：charset 最前、viewport 必写；description 影响搜索摘要；脚本优先 defer；分享卡片靠 Open Graph。
11

全局属性、字符实体与编码

所有标签都能用的属性、特殊字符怎么显示，以及乱码的根源。

11.1 全局属性

属性作用
id文档内唯一标识，用于锚点、CSS、JS 定位
class可复用的类名，多个值用空格分隔
style行内样式（优先级高，尽量少用）
title悬停提示文本
lang / dir语言 / 文字方向（ltr、rtl）
data-*自定义数据属性，JS 通过 dataset 读取
hidden布尔属性，隐藏元素（等于 display:none）
tabindex键盘 Tab 顺序；0 可聚焦、-1 仅脚本聚焦，正数不推荐
contenteditable让元素内容可编辑
draggable / spellcheck / translate拖拽 / 拼写检查 / 是否参与翻译
aria-* / role为辅助技术补充语义（WAI-ARIA）

11.2 字符实体

HTML 中 <、>、& 有特殊含义，要显示它们本身必须写字符实体：&lt;、&gt;、&amp;。实体可以用名称或数字（十进制 &#169; / 十六进制 &#xA9;）。

显示实体说明
空格&nbsp;不换行空格，可用来阻止空白折叠
< >&lt; &gt;小于号 / 大于号
&&amp;和号
" '&quot; &#39;双引号 / 单引号
© ® ™&copy; &reg; &trade;版权 / 注册 / 商标
乱码排查

中文变「锟斤拷」或问号，几乎都是文件保存编码与 <meta charset> 声明不一致。统一用 UTF-8 保存文件，并把 charset 放在 head 最前面即可。

本节速记：id 唯一、class 可复用；data-* 存自定义数据；特殊字符用实体；编码统一 UTF-8。

12.2 原生进度、度量与弹窗

  • <progress value="60" max="100">：任务完成进度。
  • <meter value="7" min="0" max="10">：已知范围内的度量值（如评分、磁盘用量）。
  • <output>：表示计算或用户操作的结果。
  • <dialog>：原生模态框，用 JS 的 showModal() / close() 控制。
  • <template>： inert 模板片段，内容不会被渲染，供 JS 克隆复用。
  • <picture> + srcset / sizes：按视口或像素密度选择最合适的图片（响应式图片）。

12.3 常与 HTML 一起用的 Web API

本节速记：progress 表进度、meter 表度量；dialog 提供原生模态；template 存模板；picture 做响应式图片；Storage / History 等交给 JS。

可访问性、编码规范与排错

让页面对所有人可用，也让自己半年后还读得懂。

13.1 可访问性（a11y）清单

  • 每张有意义的图片都写清 alt，纯装饰图写 alt=""。
  • 每个表单控件都有关联的 <label>；错误提示用文字而非仅靠颜色。
  • 用语义标签表达结构，保持标题层级连续；导航区包 <nav>。
  • 保证键盘可达：链接/按钮天然可 Tab，自定义控件才补 tabindex 与键盘事件。
  • 文字与背景有足够对比度；不要只用颜色传达状态。
  • 需要时用 role 与 aria-label / aria-describedby 补充语义，但优先使用原生标签。
  • 给 iframe 写 title，给 video 配 <track> 字幕。

15.3 自测题（点击展开答案）

1. <!DOCTYPE html> 是 HTML 标签吗？省略会怎样？
不是标签，是文档类型声明。省略会让浏览器进入怪异模式（Quirks Mode），盒模型等渲染行为与标准不一致。
2. 标签、元素、属性三者有什么区别？
标签是尖括号关键字；元素是「开始标签 + 内容 + 结束标签」整体；属性是在开始标签里补充信息的 名="值"。
3. 哪些是空元素？举 5 个。
img、br、hr、input、meta、link、source、col 等，它们没有内容也没有结束标签。
4. 中文页面出现乱码，最先检查哪两处？
文件本身的保存编码，以及 head 中是否最靠前写了 <meta charset="UTF-8">。二者需一致。
5. alt 与 title 的区别？
alt 是图片的替代文本，加载失败时显示、供屏幕阅读器与搜索引擎使用；title 是鼠标悬停提示，不能替代 alt。
6. target="_blank" 为什么要加 rel="noopener"？
避免新打开的页面通过 window.opener 访问并篡改原页面，属于安全与性能最佳实践。
7. GET 与 POST 该怎么选？
GET 把数据拼在 URL 上，适合搜索/筛选等无副作用请求；POST 放请求体，适合登录、写入、上传等会改变服务器状态的操作。
8. 表单里某个输入框的值没被提交，最可能是什么原因？
控件缺少 name 属性，或者被 disabled 了。只有带 name 且未禁用的控件才会被序列化提交。
9. colspan 与 rowspan 分别合并什么？
colspan 横向合并列，rowspan 纵向合并行；合并后要删除被覆盖的单元格，避免表格错位。
10. section、article、div 怎么选？
内容可独立分发（文章、帖子）用 article；有主题的分组（通常带标题）用 section；纯样式/布局容器用 div。
11. defer 与 async 的执行顺序有什么不同？
两者都并行下载；defer 等 HTML 解析完按顺序执行，async 下载完立即执行、不保证顺序。页面脚本优先 defer。
12. 为什么「样式丢失后页面仍能读」也算写得好？
说明文档用了正确的语义标签与标题层级，内容顺序本身就有逻辑。这对屏幕阅读器、搜索引擎、弱网环境都很重要。
